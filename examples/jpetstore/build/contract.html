확인이 필요한 질문

Q1 → 고객사 운영자/현업
원본 시스템은 고객 본인만 자기 주문을 볼 수 있습니다. 상담 에이전트가 고객 ID만으로 다른 고객의 주문을 조회하도록 허용할까요? 허용하지 않으면 게이트웨이에서 사용자 신원을 주입하는 방식으로 바꿔야 합니다.
Q2 → 고객사 보안 담당
주문 대리 접수는 고객 계정으로 로그인해야 합니다. 위임 계정 자격증명을 런타임 비밀(환경변수/Vault)로 주입하는 방식을 허용합니까? 고객별 위임이 필요하면 SSO 토큰 교환 방식으로 설계를 바꿔야 합니다.
Q3 → 고객사 현업
에이전트의 쓰기 작업(주문 접수)을 허용합니까? 허용 시 1회 주문 수량·금액 상한이 필요합니까?
Q4 → 고객사 운영자
주문 상태 코드는 소스상 'P'만 확인됩니다. 운영 DB에 다른 상태 코드(배송중, 완료 등)가 있습니까?
Q5 → 고객사 운영자
아이템 상태(item.status) 값 'P'의 의미가 소스에 정의되어 있지 않습니다(에이전트 평가 E2에서 코드값이 그대로 노출됨). 의미(판매중/품절 등)와 전체 코드 목록을 알려 주시면 get_product_details에 의미 변환을 추가하겠습니다.

search_products

조회검토 대기 UC-1 상품 검색

상품명을 키워드로 검색한다. 공백으로 구분한 여러 키워드는 OR 조건이며 대소문자를 무시한다. 가격·재고는 get_product_details로 이어서 조회한다.

입력
keywordstring검색어. 예: 'fish', 'golden retriever'
반환product_id, name, category_id, description
접근 데이터product (조회 전용)
원본과 다른 점
  • 원본은 여러 키워드가 같은 상품에 매칭되면 중복 행을 반환하지만 tool은 중복을 제거한다.
  • 원본은 앞에 공백이 있는 검색어에서 빈 키워드('%%')가 생겨 전체 상품을 반환하지만 tool은 빈 키워드를 무시한다.
보호 장치
  • 입력 가공(원본 로직 재현): lowercase
  • 입력 가공(원본 로직 재현): split_whitespace
  • 입력 가공(원본 로직 재현): wrap_like_percent
  • 입력 가공(원본 로직 재현): strip_html(description)
  • 파라미터 바인딩(SQL 인젝션 차단), 최소권한 DB 계정으로 실행
  • 반환 금지 컬럼: orders.creditcard, orders.exprdate, orders.cardtype, signon.password
근거

  • src/main/java/org/mybatis/jpetstore/service/CatalogService.java:111
  • src/main/resources/org/mybatis/jpetstore/mapper/ProductMapper.xml:46
자동 검증 항목
  • 시연 화면과 결과 일치: UC-1/search-products {'keyword': 'fish'}
  • SQL 인젝션 문자열은 값으로만 처리
  • 다중 키워드 OR
구현 상세 (개발자용)
SELECT DISTINCT p.productid AS product_id,
       p.name,
       p.category AS category_id,
       trim(regexp_replace(p.descn, '<[^>]*>', '', 'g')) AS description
FROM product p
WHERE lower(p.name) LIKE ANY (
  SELECT '%' || k || '%'
  FROM regexp_split_to_table(lower(trim(#{keyword})), '\s+') AS k
  WHERE k <> '')
ORDER BY p.productid
LIMIT 50

get_product_details

조회검토 대기 UC-2 상품 상세·가격·재고

상품 ID로 상품 정보와 판매 단위(item)별 가격, 재고 수량을 한 번에 조회한다. 주문 대리 접수(place_order)에 쓸 item_id도 여기서 얻는다.

입력
product_idstring상품 ID. 예: 'FI-SW-01' (search_products 결과의 product_id)
반환product_id, name, item_id, variant, list_price, stock_qty, status
접근 데이터inventory, item, product (조회 전용)
원본과 다른 점
  • 원본 화면 두 개(상품 목록, 아이템 상세의 재고)에 나뉜 정보를 한 tool로 합성한다.
  • 원가(unitcost)·공급사(supplier)는 상담 용도에 불필요하므로 제외한다.
보호 장치

  • 반환 금지 컬럼: orders.creditcard, orders.exprdate, orders.cardtype, signon.password
근거

  • 시연 단계 UC-2/view-item (실제 값 ['EST-1'])

자동 검증 항목

구현 상세 (개발자용)
SELECT p.productid AS product_id,
       p.name,
       i.itemid AS item_id,
       concat_ws(' ', i.attr1, i.attr2, i.attr3, i.attr4, i.attr5) AS variant,
       i.listprice AS list_price,
       v.qty AS stock_qty,
       i.status
FROM item i
JOIN product p ON p.productid = i.productid
LEFT JOIN inventory v ON v.itemid = i.itemid
WHERE i.productid = #{product_id}
ORDER BY i.itemid
LIMIT 50

list_products_by_category

조회검토 대기 UC-4 카테고리별 상품 목록

카테고리의 상품 목록을 가격대(최저·최고가)와 총 재고와 함께 조회한다. category_id는 FISH, DOGS, CATS, REPTILES, BIRDS 중 하나다(대소문자 무시). 예: "강아지 상품 뭐 있어요?" → DOGS. 상품별 상세는 get_product_details를 쓴다.

입력
category_idstring카테고리 ID: FISH, DOGS, CATS, REPTILES, BIRDS 중 하나
반환category_id, category_name, product_id, name, description, min_price, max_price, total_stock
접근 데이터category, inventory, item, product (조회 전용)
원본과 다른 점
  • 원본은 카테고리 ID 대소문자를 구분하지만 tool은 대문자로 변환한다.
  • 원본 화면에 없는 가격대·총 재고를 아이템·재고 테이블에서 집계해 추가한다.
보호 장치
  • 입력 가공(원본 로직 재현): uppercase(category_id)
  • 입력 가공(원본 로직 재현): strip_html(description)
  • 파라미터 바인딩(SQL 인젝션 차단), 최소권한 DB 계정으로 실행
  • 반환 금지 컬럼: orders.creditcard, orders.exprdate, orders.cardtype, signon.password

구현 상세 (개발자용)
SELECT c.catid AS category_id,
       c.name AS category_name,
       p.productid AS product_id,
       p.name,
       trim(regexp_replace(p.descn, '<[^>]*>', '', 'g')) AS description,
       min(i.listprice) AS min_price,
       max(i.listprice) AS max_price,
       coalesce(sum(v.qty), 0) AS total_stock
FROM category c
JOIN product p ON p.category = c.catid
LEFT JOIN item i ON i.productid = p.productid
LEFT JOIN inventory v ON v.itemid = i.itemid
WHERE c.catid = upper(trim(#{category_id}))
GROUP BY c.catid, c.name, p.productid, p.name, p.descn
ORDER BY p.productid
LIMIT 50

get_order

조회검토 대기 UC-3 주문 상세 조회

주문 번호와 고객 ID로 주문 상세(배송지, 금액, 상태, 주문 품목)를 조회한다. 주문 번호와 고객 ID가 일치하지 않으면 결과가 없다.

입력

반환order_id, username, order_date, status_name, total_price, ship_to, lines
접근 데이터item, lineitem, orders, orderstatus, product (조회 전용)
원본과 다른 점없음

  • 파라미터 바인딩(SQL 인젝션 차단), 최소권한 DB 계정으로 실행
  • 반환 금지 컬럼: orders.creditcard, orders.exprdate, orders.cardtype, signon.password

구현 상세 (개발자용)
SELECT o.orderid AS order_id,
       o.userid AS username,
       o.orderdate AS order_date,
       CASE s.status WHEN 'P' THEN '처리 대기(Pending)' ELSE s.status END AS status_name,
       o.totalprice AS total_price,
       json_build_object(
         'name', o.shiptofirstname || ' ' || o.shiptolastname,
         'address', concat_ws(', ', o.shipaddr1, o.shipaddr2, o.shipcity, o.shipstate, o.shipzip, o.shipcountry)
       ) AS ship_to,
       (SELECT json_agg(json_build_object(
                 'line', l.linenum, 'item_id', l.itemid, 'product', p.name,
                 'quantity', l.quantity, 'unit_price', l.unitprice) ORDER BY l.linenum)
          FROM lineitem l
          JOIN item i ON i.itemid = l.itemid
          JOIN product p ON p.productid = i.productid
         WHERE l.orderid = o.orderid) AS lines
FROM orders o
JOIN orderstatus s ON s.orderid = o.orderid
WHERE o.orderid = #{order_id} AND o.userid = #{username}
LIMIT 1

place_order

쓰기검토 대기 UC-5 주문 대리 접수

위임받은 고객 계정으로 아이템을 주문한다. 반드시 고객에게 아이템·수량·금액을 확인받은 뒤 호출한다. 결제수단은 고객 계정에 등록된 기본값을 쓰며 에이전트가 입력하지 않는다. 같은 request_id로 다시 호출하면 새 주문을 만들지 않고 처음 결과를 돌려준다.

입력
item_idstring주문할 아이템 ID. 예: 'EST-1' (get_product_details 결과의 item_id)
quantityinteger주문 수량(1 이상)
request_idstring중복 방지용 요청 ID. 같은 주문 요청을 재시도할 때 같은 값을 쓴다
반환order_id, total_price, message
접근 데이터레거시 화면 흐름: GET /cart/addItem?workingItemId={item_id} → POST /cart/update → GET /order/new → POST /order/new → POST /order/new
원본과 다른 점
  • 원본은 고객 본인이 로그인해 주문한다. tool은 런타임에 주입된 위임 계정 자격증명으로 로그인한다(Q2).
  • 배송지 별도 입력(shippingAddressRequired)은 지원하지 않는다. 계정 기본 주소로 배송한다.
보호 장치
  • 중복 실행 방지: request_id 기준으로 첫 실행 결과를 런타임에 보관하고 재호출 시 그대로 반환한다(재주문 없음)
  • 화면에 미리 채워진 값(결제수단 등)을 그대로 제출 — 에이전트가 입력하지 않음
  • 로그인 자격증명은 런타임 비밀값으로 주입 — 에이전트에게 노출되지 않음
